## Summary
Senior mobile test automation engineer with eight years in mobile quality, the last five focused on automation for Android and iOS apps in fintech and ride-hailing. I build Appium frameworks that two platforms can share, and I use native frameworks (Espresso and XCUITest) where speed and reliability matter more than reuse. I enjoy the practical problems of mobile testing: device fragmentation, flaky animations, permissions, network conditions, and keeping a weekly release train green.

## Experience

**Lead Mobile QA Automation Engineer** | Fintech super-app company | Since 2022
+ Architected an Appium + Java + TestNG framework for Android and iOS with a screen-object layer and shared business flows; about 75% of test code is shared between platforms. Platform-specific details live in thin adapters, selected at runtime.
+ Automated 260 critical journeys (onboarding with identity checks, top-up, QR payments, card controls, transfers). Smoke subset (45 tests) runs on every pull request on emulators and simulators in GitHub Actions; the full suite runs on release candidates on a cloud device farm covering 20 devices and the four most recent OS versions per platform.
+ Wrote a handful of Espresso tests for the Android login and biometrics flows and XCUITest tests for iOS payment confirmation, where Appium timing had been unreliable. These native tests run on every build in under 4 minutes.
+ Built a device-selection matrix based on production analytics, so coverage follows real user devices rather than guesswork.
+ Solved recurring flakiness: disabling animations in test builds, explicit synchronisation on accessibility identifiers, retry on session creation only, and quarantine for tests that fail twice a week. Flaky rate dropped from 14% to 3%.
+ Partnered with mobile developers to agree on accessibility identifiers as part of the definition of done.
+ Lead a team of three automation engineers; hire and onboard new members.
+ Introduced a release checklist for mobile: crash-free rate and startup time thresholds from the store consoles are checked next to test results, and a build is not promoted if either regresses by more than 1%.
+ Created reusable helpers for system dialogs, biometric prompts, deep links and push notifications, documented with examples so that developers can add flows to the suite without help.
+ Evaluated three cloud device farms against cost, device availability, queue time and debugging tools (video, logs, network capture); the recommendation saved about 30% of the yearly device budget compared with the first vendor quote.

**Mobile Test Automation Engineer** | Ride-hailing company | 2019/09 – 2022/02
+ Created the first Appium suite (Java, JUnit 5) for the rider and driver apps, 180 tests, run nightly from Jenkins on emulators plus 6 real devices in an in-house device lab.
+ Added network condition tests (slow 3G, offline) and location mocking for trip flows.
+ Tested the mobile backend with RestAssured; wrote 120 API tests for trip and pricing endpoints.
+ Cut the manual regression for each release from 3 days to 1 day.

**QA Engineer (Mobile)** | Mobile games studio | 2017/06 – 2019/08
+ Manual testing on a large device pool, compatibility matrices and performance observations.
+ Experimented with image comparison on the game canvas and settled on simple screenshot diffs with tolerance, limited to the five most visible screens.
+ Wrote the first Appium scripts in Python for the main game menu flows (about 30 tests) as a side initiative, later adopted by the team.

**Junior Tester** | Software company | 2016/01 – 2017/05
+ Functional testing of Android apps; wrote test cases and defect reports.
