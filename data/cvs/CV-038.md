## Professional Profile
API test automation engineer with eight years of experience in banking and insurance software. I specialise in service-level testing: designing API test frameworks in Java, building data-driven suites for payment and policy services, and wiring the results into CI as release gates. I returned to full-time work in 2023 and have since led the API test layer at a digital bank.

## Employment History

Senior API Test Automation Engineer, Digital bank (retail and cards)
2023/03 – Present

I am responsible for automated testing of about 60 REST services that sit behind the bank's mobile and web channels. When I joined, the API tests lived in personal Postman workspaces; there was no shared structure and the results were not visible to anyone. I proposed and then built a RestAssured and Java framework with TestNG, a common request-specification layer for OAuth2 and JWT handling, typed response models, and JSON schema validation against the OpenAPI definitions. The framework now holds roughly 1,100 tests for payments, accounts, cards and notifications.

Runs are triggered by GitLab CI on every merge request and every night against the integration environment; a failed critical-path suite blocks the merge. I created readable HTML reports with Allure, and the pipeline archives them with commit references, which our compliance team accepted as audit evidence during the last review.

I introduced consumer-driven contract testing with Pact between the card service and two consuming applications, then extended it to five more consumers. Provider verification runs in the provider's pipeline. This caught three breaking changes before they reached integration.

I also keep a smaller Postman/Newman collection that product owners can run themselves for smoke checks after deployments, and I mentor three engineers who are new to API testing. For test data I wrote SQL scripts and a small Java utility that creates customers, accounts and cards through the internal admin APIs, so tests no longer depend on shared fixtures.

Other contributions at the digital bank: I run a fortnightly "API clinic" where developers bring failing or confusing tests and we fix them together; I wrote the internal standard for naming tests, structuring request specifications and handling secrets in CI variables; and I maintain a risk matrix that maps each service to the depth of API coverage it needs (for example card-limit changes get full boundary coverage and contract checks, a read-only branch locator gets smoke checks only). I contribute estimates and test approach to refinement sessions and join incident reviews when an API defect reaches production, turning each case into a regression test within the same sprint.

API Test Automation Engineer, Insurance software company
2019/05 – 2021/08

Responsible for API automation of policy administration and claims services for two insurance products. Built a Java framework on RestAssured and JUnit 5 with data-driven tests fed from CSV files, covering premium calculation rules and claim state transitions (about 700 tests). Integrated the tests with Jenkins, producing JUnit XML results that were published to the team's dashboard. Reduced the suite execution time from 70 minutes to 18 minutes by running independent test classes in parallel and by replacing a slow downstream service with a WireMock stub.

Worked with BAs to turn business rules into decision tables, and then into parameterised tests. Reviewed test code of two other squads.
