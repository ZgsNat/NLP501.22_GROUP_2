## Purpose
Automation depth describes how far a candidate's automation work goes beyond using tools. Score the highest level for which the CV provides concrete evidence. Keyword lists do not count.

## Levels
- **L1 - Runs and maintains.** Executes existing scripts or pipelines, analyses failures, fixes locators and small breakages. Example signals: "ran the nightly regression suite", "updated locators", "triaged failed builds". Candidates who only say "familiar with Selenium" or similar sit below L1 (depth 0 to 1) and must not be scored above L1.
- **L2 - Writes new tests.** Authors new automated test scripts in an existing framework, uses data-driven tests, and writes API or UI tests. Example signals: "wrote 150 Cypress tests", "created pytest cases for the billing API".
- **L3 - Designs a framework.** Designs and builds a framework from scratch for a team: Page Object Model, fixtures, parallel execution (for example Selenium Grid), reporting (Allure), CI integration, flaky-test control. Example signals: "designed a Selenium + TestNG framework with parallel Grid and Allure".
- **L4 - Architecture and platform.** Builds test architecture used by many teams: shared libraries, test infrastructure on Kubernetes, CI quality gates that block releases, contract testing (Pact), standards and coaching. Example signals: "platform adopted by 14 squads", "quality gates in GitLab CI".

## Scoring notes
Map L1 to about 25, L2 to 50, L3 to 75 and L4 to 100 points on the 0-100 criterion scale, adjusting by strength and recency of evidence. Performance or mobile specialists are rated on the same scale inside their domain. Vague claims such as "led automation transformation" without tools, numbers or artefacts must be treated as unsupported.
